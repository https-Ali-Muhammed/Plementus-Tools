## C. activeTab, lifecycle and observation coverage

Chrome documents invocation-scoped temporary access: same-origin navigation can retain access; leaving that origin or closing the tab ends it. It does not turn a role picker, activation command or permission declaration into three grants. The action callback's tab is the capture source; with a popup configured, `onClicked` does not fire. This supports the proposed capture-before-focus-change/no-default-popup design, not an approved product UI migration. [activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [Action API](https://developer.chrome.com/docs/extensions/reference/api/action).

## D. Trust boundary and integration alternatives

BF-07 accepts exact plain-record fields, `source: "SIMULATED"`, distinct canonical HTTPS fixture origins (Plementus/Odoo.sh `.example`, GitHub exactly `https://github.com`), a construction-time synthetic coverage assertion and same-instance frozen context/request objects. Metadata fields cover tab/window/frame/document, origin/URL, permission/status/lifecycle, pending navigation/discard/incognito and page/privacy assertions. None is independently authenticated by the model. Serialization clones lose object identity; boot counters are not durable replay protection. It has no Chrome sender validation, current-review ownership, timeout producer or genuine invocation capture.

HTTP loopback origins identify invented local servers, with scheme/host/effective port unlike provider HTTPS origins. Rewriting them as GitHub or `.example`, labeling them authenticated or setting privacy/coverage booleans cannot create provider provenance. Even HTTPS loopback would not establish an authenticated provider account. Do not weaken BF-07, convert Chrome observations into supposedly genuine SIMULATED invocations, or promote its fixed output tier. A model projection, if separately approved, must remain explicitly synthetic and separate from actual browser evidence.
