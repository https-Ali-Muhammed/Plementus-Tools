## Assets, adversaries and boundaries

Protect consent, tab/site/case separation, local evidence integrity, customer/employee confidentiality, reviewed exports and Odoo behavior. Adversaries include malicious or compromised pages/iframes, forged/replayed messages, malicious notes, dependency compromise, a person reading the browser profile/downloads and accidental sharing by a legitimate operator. The page/renderer is lower trust than the worker; disk and downloaded files have separate exposure. OS/browser compromise and authorized profile access cannot be solved by an extension; local storage is not a confidentiality guarantee. No access to source, database, logs or secrets follows from a browser session.

## Permission to purpose mapping

This is a proposed target permission budget, not an existing manifest. Phase 02 inert scaffold should request no capture/site access. Add a permission only at its implementing phase, with reviewed production and development manifests (S2–S3, S7–S10).

| Permission / API surface | Purpose and timing | Grant scope / refusal and revocation |
|---|---|---|
| `activeTab` | Temporary host access after explicit extension invocation; selected-tab baseline in 03 | Browser invocation is not Start consent. Restricted pages denied. Application still binds exact origin/tab/document; no follow to unrelated tab |
| `scripting` | Programmatic ISOLATED top-frame collector after Start, 05–06; conditional MAIN only 08 | Pair with activeTab or approved host grant; no static/all-frame/all-site registration; deny injection on identity mismatch |
| `storage` | Small settings/ephemeral binding via chrome.storage in 04 | Set local/session access to TRUSTED_CONTEXTS before use; content script gets no direct settings/evidence access. No sync. IndexedDB itself does not require this manifest permission |
| `sidePanel` | Proposed investigation panel in 14 | Packaged extension UI; alternative full extension page avoids this permission. API availability is not tested support |
| Optional `webRequest` | Only if justified in 07 for nonblocking request outcome metadata | Request feature permission explicitly; no blocking/header/body extra options; refusal → capability unavailable and manual notes |
| Optional host permissions | Only if temporary activeTab grant proves insufficient for approved metadata use | Runtime request for the selected HTTPS host, never automatic blanket grant. Browser host-pattern scope can exceed app origin/port/path; worker must independently restrict exact URL origin and tab. Missing initiator/destination access → omit traffic, never broaden automatically |
| `tabs` methods/events without broad `tabs` permission | Selected tab lookup, close/navigation checks, targeted messages/badge | Do not request sensitive all-tab URL/title access as a shortcut. Validate actual API availability under activeTab; document gaps. No browsing-history collection |
| Local Blob + download link | User-reviewed export in 15 | No `downloads` permission planned; packaged UI creates/revokes object URL, clears references. Actual browser behavior to be tested |

For arbitrary customer hosts, optional host declarations may need a broad HTTPS eligibility pattern, e.g. `https://*/*`; **P01-HOST OWNER DECISION REQUIRED** before declaring it. This is not a blanket grant: request only the chosen site after a gesture and explain any browser-granted scope broader than exact origin. Prefer activeTab-only baseline; if owner rejects broad optional eligibility, omit persistent site grants and keep degraded metadata. No host list or declaration is created here. HTTP loopback/private HTTP, custom ports and enterprise host scope need explicit later fixture/policy review; no insecure customer-origin default.

Explicitly excluded from ordinary design: `<all_urls>` grants, mandatory wildcard host access, `webRequestBlocking`, `debugger`, DevTools dependency, cookies, history, clipboard, nativeMessaging, unlimitedStorage, offscreen workaround, remote code, broad web-accessible resources, externally_connectable. No permission named `permissions` is required merely to use chrome.permissions. Avoid claiming a browser grant is exact recording scope.

Revocation via permissions removal, content/session stop or tab/navigation invalidation must invalidate worker epoch before awaiting teardown; discard pending writes and expire collector leases. Permission revocation does not erase an existing case automatically; offer clear local delete and remove site grant separately, explaining both actions. Existing evidence retention remains bounded. Phase 03/04 tests must verify both permission revocation and explicit recording revocation. Unknown policy/failed initialization means OFF.

## Data minimization, redaction and export

| Data class | Allowed representation / exclusion rule |
|---|---|
| Session identity | Extension-generated case/event IDs and coarse environment alias; operational tab/document/origin binding in trusted ephemeral state, not export |
| Actions/navigation | Action category/time and allowlisted route class only; no target label/text, input value, key event, DOM dump, selectors or record identifiers |
| URLs/hosts | Parse only to check scope/classify; discard userinfo, query, fragment, raw path and host from evidence. Unknown paths become `unknown`; no hostname hash presented as anonymization |
| Network | Eligible status/method category, bounded duration and local request-ID mapping only; no request/response headers, bodies, cookies, auth, CSRF, full URLs, server IP or external request IDs |
| Errors | Allowlisted family/signature and safe source category; raw error text, arbitrary stack/file paths/locals and console objects excluded by default; unavailable when safe classification fails |
| Odoo context | Allowlisted technical model/method only if safe adapter can evidence it later; custom identifiers can be sensitive, otherwise omit. No customer record values/IDs or full RPC envelopes |
| Human notes/title/aliases | Voluntary extension UI inputs, explicitly user-stated; bounded text screened before persistence and again export, text-only display; reject uncertain/sensitive text rather than relying on secret regex alone |
| Findings/provenance | Actual evidence IDs, rule/adapter/schema versions, observed/derived/user-stated/unavailable/hypothesis, trust/capture gaps and redaction/drop counts; no raw rejected message retained in logs |

Layered pipeline: scope check → narrow extraction/category allowlist at collector → strict schema/size/identity validation and allowlist/redaction again in worker → bounded sanitized persistence → independent export validation and mandatory review. Token/PII patterns are defense in depth; they cannot recognize every business value. Deny arbitrary captured strings by default, not “sanitize everything with regex.” No debug logging of raw payloads. On sanitation failure discard affected data, record only a safe reason/count and show a gap; block affected export until excluded/resolved. If privacy cannot be assured, stop capture. Never read passwords/cookies/token stores/input values just to redact them.

Phase 08, if separately approved, may inspect only bounded eligible envelope content for safe categories; it must never retain/forward raw request/response data. Credential endpoints, login and unknown routes are excluded. Parsing full customer records merely to discard them is not an accepted design. Unsafe size/content/stream semantics → no parse, visible gap. Exact safe byte/extraction limits require Phase 08 GO/NO-GO; no hook in this phase.

Export requires user selection of a local case, current undeleted revision, preview of exact sanitized snapshot and included fields, redaction/gap report and deliberate download approval. JSON and Markdown derive from the same validated snapshot. Escape Markdown metacharacters/links; render preview as plain text, not HTML; safe generated filename without host/title secrets. Notes and Markdown can still identify people to recipients. No automatic attachment, upload, share URL, email, analytics, crash reporting or remote fonts/assets. Downloads are outside extension deletion; tell users to remove files/backups separately. Import remains deferred; a future parser would need independent schema/size/XSS validation, not trust exported files.

| Decision | Proposed choice | Alternative / tradeoff / gate |
|---|---|---|
| P01-RETENTION | One recording; stop at 30 minutes, 5,000 events or 5 MiB/case; maximum 10 retained cases / 20 MiB total; expire 24 hours from case creation including notes | Volatile-only or shorter age reduces exposure; 7-day retention aids handover but increases disk risk. Before 04; limits apply before enqueue/commit, whichever reached first |
| P01-RETENTION input limits | 16 KiB serialized message, depth 4, 32 fields, note 2,000 characters; at most 20 events/sec, burst 40; proposed 5-second collector lease renewed by eligible-event acknowledgements only, without a keepalive heartbeat | Numbers require synthetic load/noninterference validation; idle lease expiry/background throttling pauses safely and requires explicit Resume, at a usability cost to assess before accepting this proposal. Drop before processing, count gaps; cap metadata request-map too (500 in-flight, 60-second TTL proposed). Before 04–07; never raw backlog |
| P01-CRYPT storage | IndexedDB for sanitized cases; small chrome.storage.local settings; ephemeral chrome.storage.session binding; no app encryption claimed | Volatile-only until policy accepted; explicit passphrase-derived encryption may protect locked disk evidence but adds key recovery/crypto review and cannot protect unlocked UI or compromised browser. Before persisted evidence in 04 |
| P01-CRYPT key threat | Rely on managed OS/profile protection only if owner accepts residual exposure; no stored key next to ciphertext marketed as protection | If organization requires app encryption, define separate reviewed key lifecycle, locking and export policy before storage; no credential prompt or crypto implementation now |
| P01-BROWSER | Proposed Chrome API floor 120; current patched Stable on Linux as initial tested support target | Wider OS/Chromium coverage adds tests; older floor reduces API assumptions but increases branch/security burden. Approve before 02; exact OS/build still UNKNOWN / NOT TESTED |
| P01-PRODUCTION | Deny production and unclassified environments for initial capture; only separately authorized disposable test/staging actions | Later production exception requires organization/data-owner consent, session warning, action scope and passed noninterference/privacy gates; “read-only observer” does not prevent human button writes. No live use authorized now |
| P01-EXPORT | Treat even redacted exports as internal confidential; named authorized recipient chooses handling | More restrictive no-export or additional manual review for sensitive cases; redaction never guarantees anonymity. Owner/data custodian before 15 |

Expiry/deletion behavior required regardless of chosen values: filter expired cases before any read/export, purge on wake/read/write and scheduled opportunities; no claim of immediate deletion while browser/extension is off. Reaching cap stops recording visibly; do not silently evict unrelated cases or extend retention on access. User may delete one/all cases (events, notes, findings, indexes, aliases, previews/caches) with completion/failure feedback. Serialize deletion with append/export and invalidate revisions first; no successful export-after-delete. No recycle bin, sync, backup or hidden log copy. Secure physical erasure of profile storage/SSD/backups cannot be promised. Settings reset/site-grant removal are separate controls.

The implemented permission budget is **activeTab only**; no broad/persistent/optional hosts, tabs/scripting/storage permission, worker, content script, capture, telemetry or networking in production. Incognito is not allowed. CSP restricts packaged scripts, objects and extension network/form/framing. Dev adds only WXT reload tabs/scripting, localhost host/script access and worker; never distribute it or load on customer/Odoo pages. connect-src none remains and may block HMR; use production rebuild/manual reload.

A browser grant and recording consent are separate. The popup requires a deliberately typed normalized exact origin, Local Development for loopback HTTP(S) or Test/Staging for remote HTTPS, explicit site/data-owner authorization checkbox and Approve consent only action. Active/complete/non-incognito tab with valid browser ID/window/origin required; missing URL/access, credentials, restricted/store/remote-HTTP/pending URLs denied. Default ports normalize away; non-default valid ports remain exact consent scope. Production/unknown/unrelated/unauthorized declarations denied. No automatic production/Odoo detector; declarations are user stated and cannot prove organizational authorization. No live use is authorized.

Before approving, re-query and match exact tab/window/origin; invalidate on tab activation/update/close/replacement, window focus changes, permission removal, denial/revoke or popup closure. Async revisions prevent late results restoring stale consent. Access states and consent states are shown separately. No identity from page messages exists. URL paths/query/fragment/title are discarded; there is no persistence/export of scope. Future categories/exclusions and missing-signal limits are explained before consent.

**No capture before or after approval**: Start is disabled until Phase 04, and no collector exists. Consent is popup-only preview, not future recording authority. Revoke clears consent, not Chrome activeTab; close/navigate the tab or disable extension separately. Missing browser access → unavailable; reinvoke on intended tab. ActiveTab grant expiry may not emit permission removal and URL visibility does not prove injection rights. Future worker/lifecycle/document enforcement and real browser revocation tests are mandatory before capture; never broaden host grants to avoid failure.
